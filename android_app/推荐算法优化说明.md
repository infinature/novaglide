# 推荐算法优化说明

## 问题背景
用户反馈推荐页面显示的资讯数量有限且数量不多，并且下拉刷新功能使用后不会出现新的资讯内容。

## 问题分析
1. **推荐数量限制**：原算法固定限制为20篇文章
2. **下拉刷新无效**：刷新后推荐内容不变，缺乏随机性
3. **已读文章过度降权**：已读文章分数降低过多(0.3倍)，导致内容过少
4. **未登录用户内容不足**：默认推荐算法过于保守

## 优化方案

### 1. 登录用户推荐算法优化

#### 增加推荐数量
- **原来**：固定20篇文章
- **现在**：动态计算，最少30篇，最多为所有文章的80%

#### 优化已读文章处理
- **原来**：已读文章分数×0.3（过度降权）
- **现在**：已读文章分数×0.6（保留一定可见性）

#### 增加随机因子
- 每次计算时添加0.0-0.3的随机分数
- 确保每次刷新都有不同的推荐结果

#### 确保内容多样性
- 优先确保每个类别（保研、考研、留学、考公）都有3篇代表文章
- 再用剩余文章填充，保证内容覆盖全面

### 2. 未登录用户推荐算法优化

#### 增加每类别文章数量
- **原来**：每个类别3篇文章
- **现在**：每个类别6篇文章

#### 提高推荐总数
- **原来**：最多20篇文章
- **现在**：最少25篇，最多为所有文章的90%

#### 增强下拉刷新效果
- 每次刷新重新随机排序所有推荐文章
- 确保刷新后看到不同的内容排列

### 3. 下拉刷新机制优化

#### 添加刷新时间戳
- 在`NewsViewModel`中添加`refreshTimestamp`状态
- 每次下拉刷新时更新时间戳
- 将时间戳作为`remember`的依赖项，确保推荐重新计算

#### 刷新流程优化
```kotlin
// 在refreshNews()方法中添加
_refreshTimestamp.value = System.currentTimeMillis()
```

## 效果预期

### 用户体验改善
1. **内容丰富**：推荐文章数量显著增加（从20篇增加到30-50篇）
2. **刷新有效**：每次下拉刷新都能看到不同的内容排列
3. **多样性提升**：确保各类别内容均有覆盖
4. **个性化保持**：登录用户仍享受基于行为的个性化推荐

### 技术改进
1. **算法健壮性**：处理边界情况，避免内容过少
2. **刷新机制**：完善的刷新状态管理
3. **性能优化**：合理的依赖管理，避免不必要的重计算

## 兼容性说明
- 保持原有推荐算法的核心逻辑不变
- 向下兼容，不影响现有功能
- 优化主要针对内容数量和刷新体验

1. **登录状态测试**：验证个性化推荐和刷新效果
2. **未登录状态测试**：确认默认推荐内容充足
3. **下拉刷新测试**：多次刷新验证内容变化
4. **类别覆盖测试**：确认各类别都有代表性内容

通过这些优化，推荐页面将提供更丰富、更有趣的内容体验，同时保持下拉刷新的实用性。
